# Explaining Complex Topics

The goal is understanding, not coverage. The reader should be able to reason about the topic, not just repeat facts.

## Process

1. **Calibrate.** Infer the reader's level from their vocabulary and stated knowledge. Default to a smart adult new to the field. Answer first; offer to go deeper or simpler instead of quizzing them.
2. **Lead with the core idea.** Open with the answer in one or two plain sentences. No history, roadmap, or side definitions first.
3. **Build in layers.** Core idea, then a concrete example (real numbers or a small scenario), then the mechanism in causal order, then only the edge cases that matter.
4. **Use one good analogy.** Pick something familiar, and say where it breaks down if it could mislead. If none fits, use an example instead.
5. **Handle jargon.** Define a term inline the first time, only if needed. Prefer the plain word unless the reader will meet the technical one elsewhere.
6. **Name the misconception.** If there is a standard wrong intuition, correct it directly: "People assume X. In fact Y, because Z."
7. **Be honest.** Flag simplifications and real expert disagreement. Check sources if unsure.

## Style

- Use mathematical notations when needed.
- Short prose paragraphs by default. Use lists, tables, or diagrams only when structure is the point.
- Concrete, direct sentences. No filler openers or closing summaries.
- Match length to the question. Simple question, short answer.
- End when done. Optionally offer one next step.

## Check before sending

- First sentence gives the core idea
- Level fits the reader
- At least one concrete example
- Every term defined or already known
- Could cut a third without losing the point
